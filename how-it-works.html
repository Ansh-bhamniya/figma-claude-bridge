How the Figma bridge works

The bridge lets a program outside Figma read and edit the open Figma file. It is about 100 lines of plain JavaScript in four files. There is no AI inside it: it only carries messages between two programs. This page explains each part and how to build the same thing by hand.

A request travels through five places. Each arrow is a different way of passing a message.

Why it needs three pieces

Each piece exists because of one restriction. Knowing the restrictions is the main thing you need to design this yourself.

RestrictionWhat it forces
Figma plugin code (code.js) runs in a sandbox. It can touch the document, but it has no network: no WebSocket, no fetch to localhost. Something else must do the networking.
The plugin's UI (ui.html) is a normal browser iframe. It has WebSocket, but it cannot touch the document. The iframe does the networking and forwards every message to code.js with postMessage.
A browser iframe can open a connection but cannot listen for one. The plugin dials out, so a separate process must be the WebSocket server. That is the Node process.
An MCP client starts its tools as a child process and talks to it over stdin and stdout. The same Node process also speaks MCP, so one program holds both ends.

One request, step by step

This is what happens when the client calls the tool figma_document.

  1. The client writes one line of JSON to the Node process's stdin: a JSON-RPC tools/call request naming figma_document.
  2. The MCP SDK in index.js parses it and runs the handler registered for that tool.
  3. The handler calls call({ cmd: "document" }). That function picks the next number as an id, stores a waiting promise under that id in a Map, and sends {"id":1,"cmd":"document"} down the WebSocket.
  4. ui.html receives it and passes it to the sandbox with parent.postMessage({ pluginMessage: … }, "*").
  5. code.js receives it in figma.ui.onmessage, reads figma.root.name and the page list, and answers with figma.ui.postMessage({ id: 1, result: … }).
  6. ui.html receives the answer and sends it back up the WebSocket.
  7. index.js looks up id 1 in the Map, resolves the waiting promise, and the handler returns the result as text.
  8. The SDK writes the JSON-RPC response to stdout, and the client reads it.

The id is the important trick. A WebSocket is just a stream of messages with no built-in idea of "the answer to that question", so every request carries a number and the reply carries the same number back. If no reply arrives in 30 seconds, the promise is rejected with timeout.

The tools

The build steps below cover the first four. The last two were added later in the same way: one more command in code.js, one more server.tool line in index.js.

ToolWhat the plugin does
figma_documentReturns the file name, current page and list of pages.
figma_selectionWalks every selected node and its children, returning id, name, type, position, size, fills and text.
figma_screenshotFinds a node by id, exports it as PNG with exportAsync, and sends the bytes back as base64.
figma_evalBuilds an async function from a string of JavaScript and runs it with figma in scope. This one tool can do anything the Plugin API allows, including creating and editing nodes.
figma_tokensReturns the file's variable collections and variables, plus its text, effect and paint styles.
figma_componentsLoads every page and returns the local components and component sets with their properties and variants.
figma_lintWalks a node (or the selection) and returns violations computed from node numbers: fractional pixels, spacing off the 4px grid or not bound to a variable, frames without auto layout, text without a text style, unbound fills and strokes, contrast under WCAG AA, small touch targets, and sibling left edges 1 to 3px apart.

Build it yourself

You need Node.js 18 or newer, the Figma desktop app (development plugins do not load in the browser version), and a text editor.

Skills it uses

  • JavaScript with promises and async/await. The request/reply matching is a Map of promises.
  • WebSockets. One server (ws package), one browser client.
  • The Figma Plugin API. The split between sandbox code and UI iframe, and postMessage between them. Figma's plugin docs cover this in the "How plugins run" page.
  • MCP basics. A server registers named tools with input schemas; the client lists and calls them. The official SDK handles the JSON-RPC wire format for you.

Step 1. The server

mkdir -p figma-claude-bridge/server figma-claude-bridge/plugin
cd figma-claude-bridge/server
npm init -y
npm pkg set type=module
npm install @modelcontextprotocol/sdk ws zod
server/index.js
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { WebSocketServer } from "ws";
import { z } from "zod";

const PORT = 3055;
let plugin = null;          // the one connected Figma plugin
let seq = 0;                // request counter
const pending = new Map();  // id -> { resolve, reject }

// 1. WebSocket side: wait for the Figma plugin to dial in
const wss = new WebSocketServer({ host: "127.0.0.1", port: PORT });
wss.on("connection", (ws) => {
  plugin = ws;
  ws.on("message", (raw) => {
    const m = JSON.parse(raw.toString());
    const p = pending.get(m.id);
    if (!p) return;
    pending.delete(m.id);
    m.error ? p.reject(new Error(m.error)) : p.resolve(m.result);
  });
  ws.on("close", () => { if (plugin === ws) plugin = null; });
});

// 2. Send one command to the plugin and wait for the matching reply
function call(payload) {
  return new Promise((resolve, reject) => {
    if (!plugin || plugin.readyState !== 1)
      return reject(new Error("Figma plugin not connected. Run Plugins > Development > Claude Bridge in Figma."));
    const id = ++seq;
    const t = setTimeout(() => { pending.delete(id); reject(new Error("timeout")); }, 30000);
    pending.set(id, {
      resolve: (v) => { clearTimeout(t); resolve(v); },
      reject:  (e) => { clearTimeout(t); reject(e); },
    });
    plugin.send(JSON.stringify({ id, ...payload }));
  });
}

const text = (v) => ({ content: [{ type: "text", text: JSON.stringify(v, null, 2) }] });
const wrap = (fn) => async (a) => {
  try { return await fn(a); }
  catch (e) { return { isError: true, content: [{ type: "text", text: e.message }] }; }
};

// 3. MCP side: register the tools
const server = new McpServer({ name: "figma-claude-bridge", version: "0.1.0" });

server.tool("figma_document", "Current Figma file name, current page and page list", {},
  wrap(async () => text(await call({ cmd: "document" }))));

server.tool("figma_selection", "Nodes currently selected in Figma, with children, geometry, fills and text", {},
  wrap(async () => text(await call({ cmd: "selection" }))));

server.tool("figma_screenshot", "PNG screenshot of a node by id",
  { nodeId: z.string(), scale: z.number().optional() },
  wrap(async ({ nodeId, scale }) => {
    const r = await call({ cmd: "screenshot", nodeId, scale });
    return { content: [{ type: "image", data: r.base64, mimeType: "image/png" }] };
  }));

server.tool("figma_eval", "Run JavaScript against the Figma Plugin API.",
  { code: z.string() },
  wrap(async ({ code }) => text(await call({ cmd: "eval", code }))));

await server.connect(new StdioServerTransport());
Do not use console.log in this file. stdout is the MCP channel, so any stray output corrupts the protocol. Use console.error for debugging; it goes to stderr.

Step 2. The plugin

Three files. The manifest tells Figma what to load and which addresses the iframe may connect to.

plugin/manifest.json
{
  "name": "Claude Bridge",
  "id": "claude-bridge-local-dev",
  "api": "1.0.0",
  "main": "code.js",
  "ui": "ui.html",
  "editorType": ["figma"],
  "documentAccess": "dynamic-page",
  "networkAccess": {
    "allowedDomains": ["none"],
    "devAllowedDomains": ["ws://localhost:3055", "http://localhost:3055"]
  }
}
plugin/ui.html — the iframe: only relays messages
<!doctype html>
<html><body style="font:12px sans-serif;margin:8px">
<div id="s">connecting…</div>
<script>
let ws;
function connect() {
  ws = new WebSocket("ws://localhost:3055");
  ws.onopen  = () => { document.getElementById("s").textContent = "connected to Claude"; };
  ws.onclose = () => { document.getElementById("s").textContent = "disconnected, retrying…"; setTimeout(connect, 2000); };
  // server -> sandbox
  ws.onmessage = (e) => parent.postMessage({ pluginMessage: JSON.parse(e.data) }, "*");
}
connect();
// sandbox -> server
onmessage = (e) => {
  const m = e.data.pluginMessage;
  if (m && ws && ws.readyState === 1) ws.send(JSON.stringify(m));
};
</script></body></html>
plugin/code.js — the sandbox: the only part that touches the document
figma.showUI(__html__, { width: 220, height: 60 });

const AsyncFunction = Object.getPrototypeOf(async function () {}).constructor;

// Turn a Figma node into plain JSON, recursively
function describe(n) {
  const o = { id: n.id, name: n.name, type: n.type };
  if ("x" in n) { o.x = n.x; o.y = n.y; o.width = n.width; o.height = n.height; }
  if ("fills" in n && n.fills !== figma.mixed) o.fills = n.fills;
  if ("characters" in n) o.characters = n.characters;
  if ("children" in n) o.children = n.children.map(describe);
  return o;
}

figma.ui.onmessage = async (msg) => {
  const reply = (data) => figma.ui.postMessage({ id: msg.id, ...data });
  try {
    if (msg.cmd === "selection") {
      reply({ result: figma.currentPage.selection.map(describe) });
    } else if (msg.cmd === "document") {
      reply({ result: {
        file: figma.root.name,
        page: figma.currentPage.name,
        pages: figma.root.children.map((p) => ({ id: p.id, name: p.name })),
      } });
    } else if (msg.cmd === "screenshot") {
      const node = await figma.getNodeByIdAsync(msg.nodeId);
      const bytes = await node.exportAsync({ format: "PNG", constraint: { type: "SCALE", value: msg.scale || 1 } });
      reply({ result: { base64: figma.base64Encode(bytes) } });
    } else if (msg.cmd === "eval") {
      const fn = new AsyncFunction("figma", msg.code);
      const out = await fn(figma);
      reply({ result: out === undefined ? null : out });
    } else {
      reply({ error: "unknown cmd " + msg.cmd });
    }
  } catch (e) {
    reply({ error: String(e && e.message || e) });
  }
};

Step 3. Load the plugin in Figma

  1. Open the Figma desktop app and open any file.
  2. Menu: Plugins > Development > Import plugin from manifest… and choose plugin/manifest.json.
  3. Run it: Plugins > Development > Claude Bridge. A small window says "connecting…" and retries every 2 seconds until the server is up.

Step 4. Test it with no AI at all

The MCP Inspector is a small web page that acts as an MCP client. It starts your server, lists the tools and lets you call them by clicking. 

npx @modelcontextprotocol/inspector node /full/path/to/figma-claude-bridge/server/index.js

When the Inspector starts the server, the plugin window in Figma changes to "connected". Call figma_document and you should see your file name. Then try figma_eval with: 

const r = figma.createRectangle();
r.resize(200, 100);
r.fills = [{ type: "SOLID", color: { r: 0.9, g: 0.3, b: 0.2 } }];
return r.id;

A red rectangle appears on the canvas. Everything after this point is just a different client calling the same tools.

Step 5. Connect an MCP client

Any MCP client that supports stdio servers works. For Claude Code:

claude mcp add figma-bridge --scope user -- node /full/path/to/figma-claude-bridge/server/index.js

This adds the entry below to ~/.claude.json. Other clients use the same three fields in their own config file.

"mcpServers": {
  "figma-bridge": {
    "type": "stdio",
    "command": "node",
    "args": ["/full/path/to/figma-claude-bridge/server/index.js"]
  }
}

Limits of this version

  • The plugin window must stay open. Closing it closes the WebSocket, and every tool returns "Figma plugin not connected".
  • One Figma file at a time. The server keeps a single plugin variable, so the most recent connection wins.
  • One server at a time. Port 3055 is fixed. A second client session starting a second copy of the server fails because the port is taken.
  • Large selections give large answers. describe walks every child with no depth limit.
  • figma_eval runs any code it is given. Whatever can reach the server can edit or delete anything in the open file. Undo in Figma still works.
  • No password on the socket. It listens only on 127.0.0.1, so other machines cannot reach it, but any program on the same Mac can connect to port 3055. Adding a shared secret that the plugin sends as its first message would close that gap.
  • Development only. devAllowedDomains works for plugins loaded from a local manifest. A published plugin would need a different network setup and Figma's review.
